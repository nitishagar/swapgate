## Overview

Extend SwapGate v0.1.0 to the full six-area complete set (hosted tier, test-mode billing, scheduled runs, team sharing, LLM rubrics, sec-MCP integration, registry distribution + first swap report), with end-to-end local verification gates running in CI and locally.

## Current State

v0.1.0: stdlib-only CLI+lib, 4 thin surfaces, 93 pytest + 7 vitest all offline except one skipped live test (research ledger [V] rows; `pyproject.toml:17`, `.github/workflows/ci.yml:18`). Missing everything in scope: no local-tracing e2e (Gap), no LLM rubrics, no scheduler/history, no hosted API/teams/billing, sec-MCP is consume-only, no publish workflows or swap reports. LiteLLM 1.89.0 sibling clone evidences the e2e substrate (callback signature, `mock_response`, telemetry default-on).

## Desired End State

`python -m pytest -q` green including a hermetic LiteLLM-spinning e2e suite; `swapgate build-evals --rubrics llm` available behind a hermetic default; scheduled runs recorded in an append-only local history with receipt-identical bytes; a single-instance hosted API with team API keys and test-mode Stripe+Razorpay webhooks; versioned sec-MCP log contract with round-trip e2e; generated registry manifests + publish workflows + one reviewed swap report. Verified by: full pytest, vitest, new CI e2e job green, `swapgate manifest --check` clean, webhook signature tests, team-isolation tests.

## What We're NOT Doing

- Postgres migration / multi-instance hosted operation (single SQLite-backed instance only).
- Live-money billing paths; test-mode containment enforced (Stripe `livemode==false`, Razorpay account allowlist).
- Ed25519 receipts (stays documented future).
- OTel-collector-based e2e (excluded by research); sec-MCP as a runnable third-party system (only our contract + reference emitter).
- Release tagging (user's call). Benchmark suite (suites stay small per research bound).

## Approach

Seven ordered phases, each shippable and gate-verified. Key decisions, each tied to its invariant: litellm enters as a **test-only extra** (`.[e2e]`, `litellm>=1.89,<2`), never imported by `src/` — enforced by an import-guard test with an allowlist containing only `billing.py: stripe, razorpay` (Runtime diet + scoped relaxation); e2e drives the **real CLI via `[sys.executable, "-m", "swapgate.cli"]` subprocess** (tests the actual surface); harness builds the **minimal `parse_litellm` shape** (`{messages, response, model}` + `status_fields`/`error_information`) from hook args (Live-payload compatibility); scheduler is **interval-based** (no hand-rolled cron parser); failure rows + exit 1 on provider exception, `last_run` advances only after completed runs, single-flight via one `BEGIN IMMEDIATE` claim transaction (Scheduled failure records); history is **stdlib sqlite3** with short-lived per-operation connections (keep `check_same_thread=True`), `WAL` mode, `busy_timeout=5000`, rollback-on-exception context managers (Replay concurrency posture for the store); hosted API is **stdlib `http.server`** threading server (framework violates diet at single-instance scale); billing uses **real SDKs** (`stripe.Webhook.construct_event`, razorpay `verify_webhook_signature`), lazily imported, test-mode only (user-confirmed); webhooks dedup on provider event id (`UNIQUE`, insert-or-ignore), invalid signatures → 400 unpersisted, secrets from env only (Webhook idempotency); teams via sha256-hashed keys + `hmac.compare_digest`, foreign records → 404 (Team indistinguishability), `ALTER TABLE … ADD COLUMN team_id` migration; manifests **generated by `swapgate manifest` to root `mcp.json`** from `TOOLS` minus handler callables, `--check` step added to the `python-gates` CI job (Registry manifests generated); unknown-`mock:` fallthrough and parser-crash behavior **pinned by tests, not changed**; Markdown fence runs **escaped** (` ``` ` → `´´´`) in Phase 1 before any frozen artifacts.

## Phase 3: Scheduled regressions + run history
### Changes
#### Scheduler — `src/swapgate/schedule.py`, CLI `run-scheduled` (+`--force`) (new)
Reads schedules file (default `./schedules.json`, `--schedules` flag): entries `{suite, baseline, candidate, judge, fail_under, max_regression, interval_hours, last_run}`. Single-flight via `claims(suite_path, baseline, candidate, claimed_at, pid)` table in `runs.db` (composite key on the first three, so same-suite multi-provider entries don't serialize each other): claim = INSERT-or-ignore in one `BEGIN IMMEDIATE` transaction; claims older than 1h TTL are treated as free (crash backstop, no skip-forever); claim row DELETEd in a `finally` after the run records (success, gate-fail, or failure row). Refuses `.pending.json` and suites lacking `metadata.approved` (exit 1, no row). Entry `judge` resolves via the CLI `_judge_for` mapping (deterministic|typed; `llm` requires a `judge_fixtures` schedule field); unknown judge → exit 1, no row. Missing `last_run` means due immediately. Single-flight is scoped per `--history` DB (claims table lives there). Per due entry: `compare()` → append run row; provider exception → failure row (NULL receipt + error). Exit: 0 all-pass-or-none-due / 2 any gate fail / 1 error. `--force` ignores due-state (for CI). `last_run` advances only after completed runs (never on skip/failure/refusal). Both `cmd_build_evals` approve branch AND `finalize_pending` stamp `metadata.approved={by:"human", at:<iso>}` (lib alignment).
#### History — `src/swapgate/history.py` (new, stdlib `sqlite3`)
`runs.db` default `./swapgate-runs.db` (+`--history` flag; tests use tmp_path). Short-lived per-operation connections, `WAL`, `busy_timeout=5000`, rollback-on-exception managers. Append-only `runs` (+`webhook_events` table reserved for P4 in the same schema migration framework: `schema_version` table, additive migrations only).
#### CI dogfood — `.github/workflows/ci.yml`
New job `scheduled-selftest` (triggers: weekly `schedule:`, `workflow_dispatch`, and every push): `pip install -e .`, then `run-scheduled --schedules examples/scheduled/schedules.json --history /tmp/sched-runs.db --force` twice (second run: nothing due, exit 0). The checked-in `examples/scheduled/selftest-suite.json` carries `metadata.approved` (generated once via CLI `--approve`); the push trigger makes the identical commands PR-verifiable.
#### Tests — `tests/test_schedule.py`, `tests/test_history.py` (new)
Due/skip/`--force`, claim single-flight (two overlapping invocations in threads → one executes; stale claim reaped after TTL), approval refusal ×2, failure-row + exit 1, `last_run` advanced on success only (asserted unchanged on skip/failure/refusal), receipt-identity byte-diff vs CLI modulo `test_golden.VOLATILE`, append-only re-run.

### Changes

`swapgate serve --port --history --key` (exit 0 clean SIGTERM/SIGINT shutdown; exit 1 bind failure/config error — both tested, incl. a port-conflict test).
